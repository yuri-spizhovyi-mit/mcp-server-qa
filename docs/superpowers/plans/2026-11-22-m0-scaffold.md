# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An empty but real repo: two installable packages, exact pins, the `req` marker and a traceability check that CI enforces on Ubuntu and Windows, plus lesson 00.

**Architecture:** Two distributions in one repo, each with its own `pyproject.toml` and src layout (`energy_mcp/src/energy_mcp`, `mcpqa/src/mcpqa`). A root `requirements.txt` pins direct dependencies exactly and installs both packages editable. `scripts/rtm.py` reads `@pytest.mark.req` from the tests' source (AST, no imports), checks it against `docs/requirements.csv`, and writes `docs/rtm.md` and `docs/rtm.csv`. Its own tests run inside pytest, so a traceability gap fails CI.

**Tech Stack:** Python 3.12, hatchling 1.33.0, mcp 2.3.0, pytest 9.2.0, pytest-timeout 2.4.0, PyYAML 6.0.4, GitHub Actions (`actions/checkout@v7`, `actions/setup-python@v7`).

**Spec:** [`docs/plan.md`](../../plan.md), milestone 0, plus [`CLAUDE.md`](../../../CLAUDE.md).

## Global Constraints

- Python 3.12. `requires-python = ">=3.12"` in both packages.
- Exact pins in `requirements.txt` (`name==version`); packages declare ranges (`mcp>=2.3,<3`). Recorded as ENV-D1.
- No API keys, no secrets, no paid service anywhere; CI never references `secrets.`.
- Every test function carries `@pytest.mark.req("ID")` (or module `pytestmark`). IDs match `^(ENV|SRV|AUTH|PROTO|CONT|SEC|AGT|GATE)-\d{2}$`.
- `mcpqa` never imports or depends on `energy_mcp`.
- All text files are LF in the repo (`.gitattributes`: `* text=auto eol=lf`); Windows runners check out with `core.autocrlf=true`.
- Commands run in **Windows PowerShell** from `C:\Users\yspizhoviy\mcp-server-qa`, using `.\.venv\Scripts\python`.
- Data is synthetic (nothing in M0 needs data).
- The owner is asked before creating the GitHub repo, before merging, tagging or releasing.

## Review Focus

1. **CRLF checkout on the Windows runner** must not make the matrix look stale: `test_crlf_checkout_is_not_stale` (Task 2), plus `.gitattributes` (Task 1, asserted in Task 3).
2. **`requirements.csv` saved by Excel on Windows** carries a UTF-8 BOM; the first column must still read as `id`: `test_catalogue_with_bom_is_read` (Task 2).
3. **Tests in subfolders, test classes and `async def` tests** (M6 adds `tests/agent/`) must be traced, not silently skipped: `test_subfolder_class_and_async_tests_are_traced` (Task 2).
4. **A duplicated or misspelled ID in the catalogue** (`ENV-1`, `env-01`, two `ENV-03` rows) must be reported, not merged: `test_duplicate_and_malformed_ids_are_reported` (Task 2).
5. **A stale local venv** whose installed versions differ from `requirements.txt` must fail fast rather than pass on the wrong SDK: `test_installed_versions_match_pins` (Task 1).

### Task 2: Traceability matrix and its check (ENV-04)

**Files:**
- Create: `scripts/rtm.py`
- Modify: `docs/requirements.csv` (add ENV-04, risk `high`)
- Create (generated): `docs/rtm.md`, `docs/rtm.csv`
- Test: `tests/test_traceability.py`

**Interfaces:**
- Consumes: `docs/requirements.csv` format from Task 1; `pytest.ini` `pythonpath = scripts`.
- Produces, in `scripts/rtm.py` (adapted from llm-agent-qa's `scripts/rtm.py`, same CSV and Markdown shape):
  - `ROOT: Path` (repo root)
  - `catalogue(path: Path) -> list[dict[str, str]]`, read with `encoding="utf-8-sig"`
  - `links(root: Path) -> tuple[dict[str, list[str]], list[str]]`: scans `root/"tests"` recursively for `test_*.py`; test IDs are `tests/<posix path>::<name>` or `tests/<path>::<Class>::<name>` for methods of `Test*` classes; handles `def` and `async def`; function decorators override module `pytestmark`; a class's `pytestmark` or decorators apply to its methods
  - `problems(rows, found, untraced) -> list[str]`
  - `render_csv(rows, found) -> str`, `render_md(rows, found) -> str` (LF newlines)
  - `write(root: Path = ROOT) -> None` writes `docs/rtm.csv`, `docs/rtm.md` as UTF-8 bytes
  - `check(root: Path = ROOT) -> list[str]`: problems plus staleness; staleness compares with `read_text(encoding="utf-8")`, which already folds CRLF to LF
  - `main(argv: list[str] | None = None) -> int`: `--check` (verify only), `--root PATH` (default `ROOT`); prints each problem to stderr; returns 1 if any, else 0 and prints `traceability complete: N requirements, rtm up to date`
- Problem messages, exactly:
  - `"{id} has no test"`
  - `"{id} is cited by {tests joined by ', '} but not catalogued in docs/requirements.csv"`
  - `"{test_id} cites no requirement"`
  - `"{id} is catalogued twice"`
  - `"{id} is not a valid requirement ID"` (regex in Global Constraints)
  - `"{id} has risk {risk!r}; use low, medium or high"`
  - `"docs/rtm.csv is stale: run python scripts/rtm.py"` (same for `docs/rtm.md`)

- [ ] **Step 1: Write the failing tests** in `tests/test_traceability.py`, all `@pytest.mark.req("ENV-04")`. A helper `make_repo(tmp_path, rows: list[tuple[str, str]], tests: dict[str, str]) -> Path` writes `docs/requirements.csv` (rows are `(id, risk)`, area `Environment`, requirement text `"r"`) and each `tests/<relpath>` with the given source.
  - `test_complete_repo_has_no_problems`: one row `ENV-01`, one test citing it; after `rtm.write(root)`, `rtm.check(root) == []`.
  - `test_test_without_req_is_reported`: a test with no marker → `"tests/test_a.py::test_x cites no requirement"` in `check`.
  - `test_uncatalogued_id_is_reported`: a test citing `ENV-09` → the "not catalogued" message naming `tests/test_a.py::test_x`.
  - `test_requirement_without_test_is_reported`: row `ENV-02` with no test → `"ENV-02 has no test"`.
  - `test_stale_matrix_is_reported`: write, then add a row and its test → both stale messages; `rtm.main(["--check", "--root", str(root)]) == 1`.
  - `test_crlf_checkout_is_not_stale`: write, rewrite `docs/rtm.md` and `docs/rtm.csv` bytes with `\n` → `\r\n` → `check == []`.
  - `test_catalogue_with_bom_is_read`: catalogue written with `encoding="utf-8-sig"` → `rtm.catalogue(...)[0]["id"] == "ENV-01"` and `check == []` after write.
  - `test_duplicate_and_malformed_ids_are_reported`: rows `ENV-01` twice, `ENV-1`, `env-02`, and `ENV-03` with risk `urgent` → `"ENV-01 is catalogued twice"`, `"ENV-1 is not a valid requirement ID"`, `"env-02 is not a valid requirement ID"`, the risk message for `ENV-03`.
  - `test_subfolder_class_and_async_tests_are_traced`: `tests/agent/test_b.py` with an `async def test_y` citing `ENV-01`, and `class TestC` whose method `test_z` cites `ENV-01` via a class `pytestmark` → `links(root)[0]["ENV-01"]` contains `tests/agent/test_b.py::test_y` and `tests/test_c.py::TestC::test_z`.
  - `test_this_repo_traceability_is_complete`: `rtm.check(rtm.ROOT) == []`, with the problems joined into the assertion message.
