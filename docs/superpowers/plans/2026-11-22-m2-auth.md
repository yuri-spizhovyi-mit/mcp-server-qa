# M2 Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `energy_mcp` over HTTP becomes an OAuth 2.1 resource server. It verifies JWTs (signature, issuer, audience, expiry on an injected clock), enforces a scope per tool, resource and prompt, and a per-alert write scope with a scope hierarchy. It answers the spec's 401 and 403 challenges, serves RFC 9728 metadata, and rate-limits each principal on a fake clock. stdio takes its identity from the environment. Plus lesson 02.

**Architecture:** approach A, approved by the owner on 2026-11-22: our own HTTP edge in front of the SDK.
- `edge.py` is one ASGI layer around the SDK's `streamable_http_app()`. For `/mcp` it reads the body, then answers 401 (token), 429 (rate limit) or 403 (scope) itself. Otherwise it hands the request on with `scope["user"]` set, so the SDK's session-ownership check still works, and with the SDK's `auth_context_var` set. It also serves the metadata.
- `tokens.py` verifies JWTs and implements the SDK's `TokenVerifier` protocol.
- `scopes.py` is the pure scope policy, shared by the edge and by `access.py`.
- `access.py` holds `ScopeGuard`, an SDK middleware that enforces the same policy again on every transport: the second line of defence and the only line on stdio. It also resolves who the caller is.
- `ratelimit.py` holds a fixed-window counter per principal.

**Tech Stack:** Python 3.12, mcp 2.3.0, PyJWT 2.15.1 with cryptography 50.0.2 (both already installed as mcp dependencies; now pinned directly), starlette and uvicorn as shipped with mcp, httpx2's `ASGITransport` for in-process HTTP tests, pytest 9.2.0, anyio.

**Spec:** [`docs/plan.md`](../../plan.md), milestone 2, plus [`CLAUDE.md`](../../../CLAUDE.md), plus the owner-approved calls below. The spec rules come from the MCP authorization pages for 2026-07-28 and 2025-11-25 (read 2026-11-22), RFC 6750 §3, RFC 9068 and RFC 9728. The SDK facts were checked by throwaway spikes on the installed mcp 2.3.0 on 2026-11-22.

## What the SDK and the spec say (checked, not guessed)

| Case | mcp 2.3.0 with `token_verifier` + `AuthSettings` | Spec | Ours |
|---|---|---|---|
| No token | 401 `Bearer error="invalid_token", error_description="Authentication required", resource_metadata=...` | 401; RFC 6750 §3: no error code when the request has no credentials; `scope` SHOULD be in the challenge | 401 `Bearer resource_metadata="...", scope="..."` (F-10, F-11) |
| Bad or expired token | 401, same header as "no token" | Invalid or expired tokens MUST get 401 | 401 `error="invalid_token"`, `resource_metadata`, `scope` |
| Token expiry | re-checked against `time.time()` in `BearerAuthBackend` | | checked on the injected clock (F-09) |
| Scope missing | only `required_scopes`, one list for the whole server; 403 `insufficient_scope` without a `scope` parameter | SHOULD 403 with `error="insufficient_scope"`, `scope=` the scopes needed, `resource_metadata` | 403 per tool, resource and prompt (AUTH-D1) |
| Scope hierarchy | none | 2026-07-28: servers MUST account for scope hierarchies, a broader scope implying narrower ones | `alerts:write` implies `alerts:write:ALR-NNNN` (AUTH-D4) |
| Metadata `scopes_supported` | copied from `required_scopes`; absent when that is unset | optional; "the minimal set of scopes necessary" | our four base scopes (F-12) |
| Metadata path | `/.well-known/oauth-protected-resource/mcp` | that path or the root well-known URI | same path |
| JSON-RPC batch (array) POST | 400 `-32600` "Body must be a single JSON-RPC request" | | relied on, and pinned by a test |
| Session used with another principal's token | 404 "Session not found" (it reads `scope["user"]`) | | relied on; the edge sets `scope["user"]` |
| Token seen inside a tool or middleware | `get_access_token()` works when `auth_context_var` is set around the SDK app, on both revisions (spike) | | used by `current_identity` |
| Rate limiting | none | not in the spec | ours (AUTH-D2) |
| stdio | no auth | SHOULD NOT follow the spec; credentials from the environment | `ENERGY_MCP_SCOPES`, `ENERGY_MCP_OPERATOR` (AUTH-D3) |

## Owner-approved calls (2026-11-22)

- **AUTH-D1:** a missing scope gets HTTP 403, header `Bearer error="insufficient_scope", scope="<needed>", resource_metadata="<url>", error_description="<fixed text>"`, before the SDK sees the call.
- **AUTH-D2:** a rate-limited call gets HTTP 429 with `Retry-After: <whole seconds, rounded up>`. The count is per principal `(iss, sub, client_id)`: every authenticated request to `/mcp` counts, refused ones included. It is a fixed window, by default 60 requests per 60 s, on the injected clock. stdio is not limited.
- **AUTH-D3:** stdio and in-process identity comes from `Identity(operator, scopes)`. The CLI reads `ENERGY_MCP_SCOPES` (space-separated; default `meters:read alerts:read reports:read`) and `ENERGY_MCP_OPERATOR` (default `local-operator`). An unknown scope or a malformed operator stops the server at startup (exit 2). Without HTTP, a refused tool call is a tool error (`isError`) `Not allowed: this call needs scope <s>`, and a refused resource or prompt is `-32602` with the same text. My call within the approval: the refusal shapes on stdio.
- **AUTH-D4:** the scopes are:
  - `meters:read` for `list_meters` and `get_readings`.
  - `alerts:read` for `list_alerts` and `prompts/get investigate_alert`.
  - `alerts:write` or `alerts:write:<alert_id>` for `acknowledge_alert`.
  - `reports:read` for `resources/read`.

  Listing (`tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`) and every other method need only a valid token. `alerts:write` covers every `alerts:write:ALR-NNNN`, and nothing else implies anything. When `alert_id` is missing or doesn't fullmatch `ALR-[0-9]{4}`, the call needs `alerts:write`, so no caller text ever reaches a challenge.
- **AUTH-D5:** a token is accepted only if all of these hold:
  - It is signed RS256 with the configured public key, and its header `typ` is `at+jwt` or `application/at+jwt` (RFC 9068 §4).
  - It has `iss`, `aud`, `exp`, `iat`, `sub`, `client_id`, `jti` and a string `scope`, as RFC 9068 §2.2 requires.
  - `iss` and `aud` match exactly.
  - On the injected clock, with no leeway: `exp > now`, `iat <= now`, and `nbf <= now` when present.
  - `sub` and `client_id` fullmatch `[A-Za-z0-9._-]{1,64}`, because `sub` becomes `acknowledged_by`, which other callers' models read.
- **AUTH-D6:** `--transport http` refuses to start without `--public-key` and `--issuer`. There is no unauthenticated HTTP mode. A server built for HTTP has the fallback identity `Identity("unauthenticated", frozenset())`, so if the edge were bypassed the guard refuses everything.
- The `acknowledge_alert` write takes a lock (deferred from the M1 review).

## Review Focus

1. **A refused call still changes the world** (the 401, 403 or 429 comes after the SDK ran the tool): `test_refused_calls_leave_the_world_unchanged` (Task 4) and `test_limited_call_never_reaches_the_server` (Task 5) compare `world.digest()`.
2. **Caller text in a challenge header** (quotes, CR/LF or a long string in `alert_id` become header injection): `test_challenge_never_carries_caller_text` (Task 4).
3. **A body the edge can't read slips a write past the scope check** (JSON array, invalid JSON, wrong content type, `params` not an object): `test_unreadable_bodies_cannot_write` (Task 4). The SDK must refuse each one, and the world stays unchanged.

5. **A fresh token resets the rate window** for the same principal: `test_new_token_same_principal_stays_limited` (Task 5).

  2. No `Authorization: Bearer <t>` (the scheme is case-insensitive; a query-string token is ignored): 401 `Bearer resource_metadata="<m>", scope="<needed, or READ_SCOPES when empty, space-joined and sorted>"`.
  3. Verifier returns `None`: 401 `Bearer error="invalid_token", error_description="The access token is invalid or expired", resource_metadata=..., scope=...`.
  4. The limiter (Task 5).
  5. `missing(token.scopes, needed)` non-empty: 403 `Bearer error="insufficient_scope", scope="<missing>", resource_metadata="<m>", error_description="This call needs more scope"`.
  6. Otherwise set `scope["user"] = AuthenticatedUser(token)` and `scope["auth"] = AuthCredentials(token.scopes)`, set `auth_context_var` around the inner call, and replay the buffered body.

  Response bodies are JSON `{"error": ..., "error_description": ...}`.
- Edge behaviour for `/.well-known/oauth-protected-resource/mcp` (GET): `ProtectedResourceMetadata(resource=..., authorization_servers=[issuer], scopes_supported=list(BASE_SCOPES), bearer_methods_supported=["header"])` from `mcp.shared.auth`, as JSON, without auth.

**Interfaces:**
- `RateLimiter(limit: int, window: float, clock: Callable[[], float])` with `hit(key: Hashable) -> float | None`. It returns `None` when the call is allowed, else the seconds until the window resets.
